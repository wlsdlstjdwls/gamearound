# 게임 사양, 그리고 "내 PC 로 돌아가나" — 설계 초안 (2026-09-17)

게임 상세에 최소/권장 사양을 싣고, 사용자가 등록한 기기로 구동 가능 여부를 판정하는 축.
지금 카탈로그에 **사양 데이터가 한 글자도 없다**(스키마, 어댑터 전수 확인).

---

## 0. 실측으로 먼저 정한 것 (2026-09-17)

추측으로 적지 않는다. 스팀 두 경로를 직접 때려 봤다.

1. **`appdetails` 는 사양을 준다.** `pc_requirements`, `mac_requirements`, `linux_requirements`.
   값은 구조체가 아니라 **HTML 문자열**이다(`<strong>라벨:</strong> 값` 이 `<li>` 로 나열).
2. **`GetItems`(배치 경로)는 사양을 안 준다.** `include_platforms`, `include_full_description` 을 켜고 받아 봤지만
   응답 키에 requirement 계열이 없다. **사양은 배치로 못 받는다. 게임당 1회 단건 조회다**(§2).
3. **덤: `GetItems` 가 스팀덱 호환 등급을 공짜로 준다.**
   `platforms.steam_deck_compat_category`, `steam_os_compat_category`, `steam_machine_compat_category`.
   우리는 이미 `include_platforms: true` 로 받고 있는데 **파서가 이 값을 버리고 있다.**
   요청 수가 늘지 않는다. 이 축에서 제일 싼 수확이다.

콘솔(PS, Xbox, Switch)은 사양 개념이 없다. **이 축은 PC 전용이다**(steam, epic, gog).

## 1. 수집

### 언어는 영어로 받아 파싱한다

`l=koreana` 로 받으면 라벨이 "운영 체제:", "프로세서:" 로 번역돼 오는데, 번역이 게임마다 흔들린다.
영어 라벨(`OS:`, `Processor:`, `Memory:`, `Graphics:`, `DirectX:`, `Storage:`)이 훨씬 안정적이다.
**화면 문구는 우리가 한국어로 만든다.** 값(칩 이름)은 어차피 영문이다.

우리는 이미 ko/en 두 응답을 받는 경로가 있다(`parse-app-details`). 영문 쪽에서 뽑으면 요청이 안 는다.

### 비용 — 사양은 거의 안 변한다

한 번 받으면 끝이다. 재발매나 대규모 패치 때만 바뀐다. 그래서:

- **1회 백필**(스팀 본편 대상) + 그 뒤로는 **신규 등록분만**
- 갱신 주기는 길게(분기 또는 수동). 가격처럼 매일 돌릴 것이 아니다
- 백필 예산은 본편 수 곱하기 실측 초/건으로 계산한다. 추정으로 잡지 않는다(gog 가 추정 283초에 실측 760초였다)

### 다른 스토어 — 확인 필요

GOG 와 Epic 도 상세에 사양을 싣지만 **형식은 실측 전이다.** 추측해서 적지 않는다(§9).
스팀만으로도 PC 게임 대부분이 덮인다. 1단계는 스팀으로 시작한다.

## 2. 저장

### game_requirements — 사양 원본과 파싱 결과

| 컬럼 | 뜻 |
|---|---|
| `gameId`, `platform` | 어느 게임, 어느 스토어에서 온 사양인가 |
| `osFamily` | `windows` / `mac` / `linux` |
| `tier` | `minimum` / `recommended` |
| `rawHtml` | **원문을 버리지 않는다** |
| `osText`, `cpuText`, `gpuText`, `directxText`, `noteText` | 파싱된 문자열 그대로 |
| `ramMb`, `vramMb`, `storageMb` | 숫자로 뽑힌 값. 못 뽑으면 null |
| `parseVersion`, `parseConfidence` | 어느 파서 판이 뽑았나, 얼마나 믿는가 |

**`rawHtml` 을 남기는 이유**: 파서는 반드시 고치게 된다. 원문이 있으면 재수집 없이 다시 돌린다.
스팀에 다시 수만 번 요청하는 일과 DB 를 한 번 훑는 일의 차이다.

### game_requirement_parts — "A 또는 B" 를 담는 자리

실제 값은 이렇게 온다.

```
Processor: INTEL CORE I5-8400 or AMD RYZEN 3 3300X
Graphics:  NVIDIA GEFORCE GTX 1060 3 GB or AMD RADEON RX 580 4 GB
```

**한 칸에 후보가 여럿이다.** 컬럼 하나로는 비교를 못 한다.
`requirementId`, `kind`(`cpu` / `gpu`), `modelId`(사전 참조), `rawText`, `isAlternative`.

판정은 **후보 중 하나만 넘으면 충족**이다. 인텔 유저에게 라이젠 기준을 들이대면 안 된다.

### games 또는 game_platforms 에 붙는 것

- `steamDeckCompat` (`verified` / `playable` / `unsupported` / `unknown`) — §0 의 공짜 데이터
- 맥, 리눅스 **네이티브 지원 여부**는 `platforms` 플래그에서 온다. 사양보다 이게 먼저다(§5)

## 3. 하드웨어 사전 — 여기가 이 기능의 전부다

"GTX 1060 을 가진 사람이 RX 580 권장 게임을 돌릴 수 있나" 에 답하려면 **두 부품을 같은 자로 재야 한다.**
그 자가 없으면 판정은 불가능하고, 억지로 하면 거짓말이 된다.

### gpu_models, cpu_models (이름 규칙은 매장 설계서 §1)

`canonicalName`, `vendor`, `series`, `generation`, `releaseYear`,
`isMobile`(노트북용), `vramMb`, **`perfScore`**, `aliases[]`.

- `aliases` 가 실무의 절반이다. "GTX 1060", "GeForce GTX 1060 3GB", "NVIDIA GTX1060" 이 다 같은 물건이다.
  우리는 이미 별칭 매칭 자산이 있다(`game_aliases`, 정규화, trigram). 같은 방식을 쓴다
- **노트북 GPU 는 별도 모델이다.** 이름이 같아도 성능이 다르다. `isMobile` 을 안 가르면 노트북 사용자에게 거짓 통과를 준다

### perfScore 를 어디서 얻나 — 미해결

PassMark, 3DMark 같은 벤치마크 점수는 **상업적 재배포에 제한이 있다.** 확인 없이 긁어 쓰지 않는다.

갈래 셋:

- **(a) 자체 티어표를 손으로 만든다.** GPU 200개, CPU 150개면 국내 사용자 대부분을 덮는다.
  한 번 만들면 분기마다 몇 줄 추가다. **권장**
- (b) 라이선스가 열린 공개 데이터셋을 찾는다. 있으면 최선, 없으면 (a)
- (c) 판정을 포기하고 사양 원문만 보여준다. 1단계가 이것이다

(a)로 가되 **점수는 상대 등급이면 충분하다.** 절대 수치를 흉내 낼 필요가 없다.
"이 게임 권장 = 티어 12, 당신 GPU = 티어 14" 면 답이 나온다.

## 4. 내 기기

### user_devices

`userId`, `label`("집 데스크탑", "회사 노트북"), `osFamily`, `osVersion`,
`cpuModelId`, `gpuModelId`, `ramMb`, `storageFreeMb`, `source`(`manual` / `detected`), `isPrimary`.

- **여러 대를 등록한다.** 데스크탑과 노트북의 답이 다르다
- 비회원도 쓰게 한다. 기기 하나를 브라우저에 저장하고, 로그인하면 계정으로 옮긴다.
  로그인을 요구하면 이 기능을 아무도 안 쓴다

### 자동 감지 — 초안일 뿐이다

브라우저에서 얻을 수 있는 것과 그 한계(실측 전, 알려진 제약):

| 값 | 방법 | 한계 |
|---|---|---|
| GPU 모델 | WebGL `UNMASKED_RENDERER_WEBGL` | 크롬 계열은 모델명이 나오지만 사파리는 "Apple GPU" 로 뭉갠다. 파이어폭스는 가리기도 한다 |
| CPU 코어 수 | `navigator.hardwareConcurrency` | **모델명은 못 얻는다.** 코어 수만으로는 세대를 모른다 |
| RAM | `navigator.deviceMemory` | 크롬 계열만. 값이 8GB 에서 막힌다(32GB 도 8로 온다) |
| OS, 아키텍처 | UA-CH `getHighEntropyValues` | 버전이 뭉개질 수 있다 |

**그래서 자동 감지 결과를 그대로 판정에 넣지 않는다.**
감지값은 등록 폼의 **기본 선택지**로만 채우고, 사용자가 확인하고 고친다.
자동으로 채운 값과 사람이 고친 값을 `source` 로 구분해 둔다 — 틀린 판정이 나왔을 때 원인을 여기서 찾는다.

## 5. 맥은 따로 답해야 한다

- **네이티브 지원 여부가 사양보다 먼저다.** 맥 빌드가 없으면 사양을 비교할 이유가 없다.
  스토어의 `platforms.mac` 이 그 답이다
- Apple Silicon 은 브라우저가 칩을 특정하지 못한다. **사용자가 고른다**(M1 ~ M4, 무印 / Pro / Max / Ultra)
- 게임 포팅 툴킷, Crossover, Whisky 같은 우회 실행은 **우리가 보증할 영역이 아니다.**
  "네이티브 미지원" 이라고 적고 끝낸다. 억지로 "될 수도" 를 적으면 그 책임이 우리에게 온다

## 6. 판정

### 한 마디로 답하지 않는다

```
최소 미만  /  최소 충족  /  권장 충족  /  권장 이상
```

그리고 **부위별로 보여준다** — CPU, GPU, RAM, 저장공간, OS.
하나만 못 미치면 그게 병목이고, 사용자가 고칠 수 있는 정보다.
"불가" 한 마디보다 "RAM 만 8GB 모자랍니다" 가 백 배 쓸모 있다.

### 예상 옵션은 추정이라고 적는다

"권장 사양 = 1080p 높음 60fps" 는 업계 통념이지 약속이 아니다. 게임마다 다르다.
표기는 "이 정도로 예상돼요" 수준으로 하고, 단정하지 않는다.

### 모르면 모른다고 한다

사전에 없는 GPU 가 나오면 점수를 지어내지 않는다. "확인 못 한 부품" 으로 표시하고,
그 항목은 판정에서 빼되 **판정 전체에 "일부 확인 불가" 를 단다.**
조용히 통과시키는 것이 제일 나쁘다.

### 캐시

(기기, 게임) 판정은 결정적이라 캐시할 수 있다. 사양이나 사전이 바뀌면 무효화한다.
목록 필터(§7)를 하려면 이 캐시가 먼저 있어야 한다.

## 7. 화면

### 게임 상세 — "내 PC 로 돌아갈까요" 섹션

- **PC 플랫폼(steam, epic, gog)이 있을 때만 뜬다.** 콘솔 전용 게임에는 자리 자체가 없다
- 기기 미등록: 최소/권장 사양표 + "내 기기 등록하고 확인하기"
- 기기 등록됨: 판정 배지 + 부위별 표 + 기기 전환(데스크탑, 노트북)
- **스팀덱 배지**는 기기 등록과 무관하게 바로 뜬다(§0 의 공짜 데이터)
- 맥 사용자에게는 네이티브 지원 여부를 먼저 보여준다(§5)

### 설정

- `/settings/devices` 기기 목록, 추가, 수정, 기본 기기 지정

### 목록, 검색 (3단계)

- "내 기기로 돌아가는 게임만" 필터. 판정 캐시가 있어야 가능하다

## 8. 단계

1. **수집과 표시** — `game_requirements`, 스팀 파서, 백필, 상세에 사양표.
   **스팀덱 등급을 같이 줍는다**(파서 몇 줄, 요청 증가 0). 판정은 아직 없다
2. **판정** — `gpu_models`, `cpu_models`, 티어표, `user_devices`, 등록 폼, 부위별 판정
3. **자동 감지와 확장** — WebGL 감지, 맥 처리, 목록 필터, GOG/Epic 사양

1단계만으로도 "사양이 아예 없다" 는 지금 상태보다 훨씬 낫다. 그리고 1단계는 **하루짜리 일**이다.
2단계의 티어표가 이 기능의 진짜 원가다.

## 10. 1단계 구현과 실측 (2026-09-18)

커밋 `cb0a1ab`(덱 등급, 네이티브 OS), `be49724`(사양 수집과 표시).

### 형식 편차 — 무작위 60건 표본

- **응답 60/60 성공, `pc_requirements` 가 빈 게임은 0건.** 사양은 사실상 다 있다
- **권장 사양은 49/60(82%)에만 있다.** 없는 것이 정상이라 실패로 다루지 않는다
- 라벨 변종(실측 횟수): `OS *` 29, `Hard Drive` 2, `DirectX®` 1, `DirectX Version` 1, `Sound` 1.
  별표는 스팀이 "Windows 32bit 지원 종료" 주석을 달며 붙이는 것이라 라벨의 일부가 아니다
- 모르는 라벨도 실제로 온다: `Sound Card` 26, `Network` 20, `VR Support` 3, `Input` 1.
  버리지 않고 비고(`note_text`)로 모은다 — 칸을 늘릴 때 무엇이 오는지 이 문구가 알려 준다
- 단위 없는 값이 있다("256 RAM"). **null 로 둔다** — 짐작해 채우면 판정이 조용히 틀린 답을 낸다

### 백필 예산

- **1.87초/건**(30건 56초 실측). 스팀 본편 3,493건이면 약 109분
- 게임당 사양 행 2.4개. 수집 30건이 70행이었다
- 파싱 품질: 윈도우 최소 사양 30/30, 평균 `parse_confidence` 0.95(네 칸 중 3.8칸)
- **비고만 있는 덩어리는 행으로 만들지 않는다.** 노 맨즈 스카이의 권장 칸에는
  "Requires a 64-bit processor" 한 줄뿐이고, ZeroSpace 의 리눅스 칸에는 "Available with Proton" 뿐이다.
  행을 만들면 화면에 값 없는 칸이 서서 수집이 덜 된 것처럼 보인다
- 실행처는 **로컬 회선**이다(`pnpm requirements:backfill`). Actions 는 crawl-prices 만으로 이미 한도에 붙어 있다

### 덱 등급 — 요청 증가 0 확인

`GetItems` 의 `platforms` 에 실려 온다. 값 자리를 실측으로 확인했다:
엘든 링, 위쳐3 이 3(verified), 마블 라이벌즈, 칼파 2(playable), 배그 1(unsupported).
밸브가 아직 안 본 게임은 0 으로 오는데 값이 아니라 null 로 옮긴다.
**카탈로그 대부분은 등급이 없다** — 실측 10건 수집에서 6건만 등급을 받았다(나머지는 DLC 와 미평가작).

## 11. 2단계 구현과 실측 (2026-09-18)

커밋 `03760f2`(부품 사전, 후보 추출), `03ddb0c`(내 기기, 판정).

### 티어표 — 갈래 (a) 를 택했다

벤치마크 점수는 라이선스를 확인하지 않고 쓰지 않는다. 대신 **순서만** 만들었다:
GPU 20단계, CPU 17단계. 같은 티어는 "비슷한 급" 이지 "같은 성능" 이 아니라,
판정은 티어가 **같거나 높으면 충족**으로 본다(인접 티어는 게임에 따라 뒤집힌다).

**사전은 DB 표가 아니라 코드에 뒀다**(설계 §3 은 `gpu_models` 표를 그렸다).
사람이 손으로 고치는 참조 자료이고 관리자 화면 계획도 없어서, 표로 두면 마이그레이션과 시드와
표류가 붙는다. 대신 SQL 이 티어로 걸러야 하는 자리(3단계 목록 필터)를 위해
**매칭 시점의 티어를 후보 행에 박는다**. 사전이 바뀌면 `pnpm parts:rematch` 가 그 값을 갈아 준다 —
스토어에 다시 묻지 않는다(사양 원문을 남겨 둔 값어치).

기기 쪽은 반대로 **열쇠만** 저장한다. 티어표는 계속 손보는데 기기에 티어를 박으면 표를 고칠 때마다
등록된 기기를 다시 계산해야 한다. 열쇠로 두면 사전이 좋아질 때 기존 기기의 판정도 같이 좋아진다.

### 커버리지 실측

| | 문구 | 후보를 세운 문구 | 티어가 붙은 문구 |
|---|---|---|---|
| GPU | 505 | 453 | 403 (80%) |
| CPU | 517 | 344 | 314 (61%) |

**남은 구멍의 대부분은 사전 탓이 아니다.** 모델을 실제로 적은 문구만 보면 GPU 89%, CPU 91% 가 붙는다.
나머지는 스토어가 모델을 안 적은 것이다("Quad Core Processor", "DirectX 10 capable hardware").

규칙 두 개가 실측으로 바뀌었다.
- **용량 꼬리표가 열쇠에 붙어 경계 규칙에 걸렸다**("GTX 770 2GB"). 티어를 못 붙인 후보의 절반이었다.
  꼬리표를 단 이름으로 먼저 찾고 없으면 떼고 다시 본다 — "1060 3GB" 와 "6GB" 는 다른 티어라
  처음부터 떼면 그 구분이 사라진다.
- **미매칭 1위가 `i5` 33회, 2위가 `i3` 16회였는데 둘 다 사전 구멍이 아니다.** i5 는 2009년부터
  지금까지 있고 그 사이 성능이 열 배 벌어졌다. 세대를 안 적은 문구는 후보로 세우지 않는다 —
  같이 세면 화면이 "확인 못 한 부품" 을 사전 탓으로 돌린다.

### 판정과 기기

- 비회원도 쓴다(§4 의 전제). 상세 화면에서 바로 적고 브라우저에 둔다.
  판정이 순수 계산이라 서버 왕복이 없고, 규칙은 `lib/hardware/verdict` 한 곳이다
- 부품은 목록에서 고르지 않고 **적은 대로 받아 매칭기가 알아본다**. 사전이 300개가 넘어 목록이
  스크롤 벽이 되고, 사람은 자기 부품을 정식 이름으로 기억하지 않는다("1060")
- 화면 실측: 발더스 게이트 3 + i5-8400 + GTX 1060 6GB + 8GB = "최소 사양을 넘어요",
  그래픽만 GTX 750 Ti 로 바꾸면 "최소 사양에 못 미쳐요 | 그래픽 모자람"

### 아직 안 한 것

- **판정 캐시**(§6). 지금은 화면에서 그때그때 계산한다 — 게임 하나당 비교 네 번이라 쌀 뿐,
  목록 필터(3단계)를 하려면 캐시가 먼저 필요하다
- 자동 감지(§4), 맥 안내(§5), 목록 필터(§7 3단계)
- CPU 티어표의 세대 없는 문구(전체의 3분의 1)는 원천적으로 판정 불가다. 이건 사전을 키워도 안 풀린다

### 2단계로 미룬 것

- `game_requirement_parts`("A 또는 B") — 판정이 없으면 쓸 데가 없다
- `vram_mb` 는 컬럼만 있고 사실상 안 찬다. 표본 60건에 `Video Memory` 라벨이 0회였다.
  GPU 이름 뒤의 "3 GB" 는 읽지 않는다 — 그건 그 후보 카드의 사양이지 요구 VRAM 이 아니고,
  후보가 둘일 때 어느 쪽 값인지도 알 수 없다
- 맥 사용자에게 "네이티브 미지원" 을 먼저 말하는 일(§5). 지금은 누가 맥인지 모른다 —
  자동 감지(3단계)가 붙어야 할 말을 고를 수 있다
