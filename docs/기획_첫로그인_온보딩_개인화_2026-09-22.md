# 첫 로그인 온보딩 — 개인화 정보 수집 설계

작성 2026-09-22. 참고자료는 주택 공고 진단 앱의 온보딩 29장(카카오톡 전달분).
근거 설계서는 `docs/손전등_개발설계서.md`, 코드 규약은 레포 루트 `AGENTS.md`.

## 0. 한 줄

가입 직후 **한 화면에 질문 하나**로 기기와 게임 성향을 받아 두고, 그 값으로 목록, 홈, 알림 기본값을 사람마다 다르게 그린다.

## 1. 참고자료에서 가져올 것과 버릴 것

29장을 훑어 뽑은 규칙이다.

**가져온다**

| 규칙 | 근거 화면 |
|---|---|
| 한 화면에 질문 하나. 제목은 의문문, 그 아래 한 줄로 **왜 묻는지** | "생년월일을 알려주시겠어요? / 특정 나이 대에만 지원할 수 있는 공고가 있어요" |
| 답은 큰 카드로 고른다. 카드 안에 그림, 이름, 부연 한 줄 | "가족 형태가 어떻게 되시나요?" 의 3카드 |
| 고른 카드는 면 색이 바뀌고 좌상단 동그라미에 체크가 찬다 | "대학생이신가요?" |
| 답하기 전 하단 버튼은 **비활성 회색** | "취업준비생이신가요?" |
| 헷갈릴 규칙은 카드 아래 인셋 안내로 못 박는다 | "입력전에 꼭! 대학원생, 졸업유예생은 대학생에 포함이 안돼요" |
| 좌상단 뒤로, 우상단 나가기 | 결과 화면 |
| 마지막은 **결과 화면**. 받은 답으로 지금 당장 뭐가 달라졌는지 숫자로 보여준다 | "내 조건에 맞는 공고 유형은 총 15개에요" |
| 숫자 입력은 큰 글자 + 자릿수 보조 버튼 | "내 세전 소득" 의 +1,000만 원 |

**버린다**

- **그림(이모지 일러스트)**: 우리 브랜드는 그림을 안 쓴다. 대신 아이콘 + 굵은 글자 + 브랜드 보라 면으로 같은 무게를 만든다.
- **파란 계열**: 우리 악센트는 `--acc`(보라)다. `globals.css` 토큰만 쓴다(규약 §6).
- **필수 강제**: 저쪽은 공고 자격 판정이라 다 받아야 한다. 우리는 **전부 선택**이다(§5 참고).
- **15단계 길이**: 우리는 7단계, 그중 답을 꼭 받고 싶은 건 앞 3단계다.

## 2. 무엇을 받나 — "이 답이 지금 화면을 바꾸는가" 로만 고른다

물어만 보고 쓰지 않는 값은 넣지 않는다. 각 질문 옆에 **쓰이는 자리**를 적는다. 그 자리가 비면 질문을 뺀다.

| # | 질문 | 받는 값 | 곧바로 쓰이는 자리 |
|---|---|---|---|
| 1 | 주로 어디서 게임하세요? | 플랫폼 다중선택 | 목록 기본 필터, 홈 할인 줄, 가격표 정렬 |
| 2 | 이 기기 사양을 등록할까요? | `user_devices` 1행 | 상세의 "내 기기로 돌아가나" 판정 |
| 3 | 어떤 장르를 좋아하세요? | 장르 다중선택(최소 1) | 홈 추천 줄, 목록 초기 정렬 |
| 4 | 정가에 사세요, 기다리세요? | 할인 민감도 1단계 | 알림 기본 임계값, 홈 "지금이 그때" 줄 |
| 5 | 한 번 잡으면 얼마나 하세요? | 플레이타임 취향 | HLTB 기반 추천, 시간당 가격 노출 여부 |
| 6 | 구독 중인 서비스가 있나요? | 구독 다중선택 | 이미 구독에 포함된 게임을 목록에서 내려둔다 |
| 7 | 할인되면 알려드릴까요? | 웹푸시 권한 | 알림 축 전체 |

**일부러 안 받는 것**

- 생년월일, 성별, 지역: 지금 코드에 이 값을 읽는 자리가 하나도 없다. 개인정보는 쓸 자리가 생긴 회차에 받는다.
- 예산(월 지출액): 4번 할인 민감도가 같은 일을 더 적은 부담으로 한다. 금액은 사람이 답하기 꺼리고, 우리가 할 수 있는 건 임계값 하나 정하는 것뿐이다.
- 좋아하는 게임 검색: 좋아 보이지만 입력 비용이 가장 크고, 3번 장르로 80%가 대체된다. 2회차로 미룬다.

## 3. 화면 흐름

```
가입 성공
   ↓
/welcome                     0단계 — 무엇을 왜 묻는지 + 개인화 동의 + "나중에 할래요"
   ↓
/welcome/platforms           1
/welcome/device              2  (1에서 PC 를 안 골랐으면 건너뛴다)
/welcome/genres              3
/welcome/deal-style          4
/welcome/play-time           5
/welcome/subscriptions       6
/welcome/notify              7
   ↓
/welcome/done                결과 — "지금 조건에 맞는 게임 N개" + 바로 목록으로
```

- 단계를 **주소로 가른다**. 한 화면에서 상태만 바꾸면 브라우저 뒤로가기가 온보딩 전체를 빠져나간다 — 참고자료의 좌상단 뒤로와 손가락 스와이프가 같은 동작이어야 한다.
- 답은 **단계마다 즉시 저장**한다. 중간에 창을 닫아도 다음 로그인 때 그 단계에서 다시 연다(`user_profiles.onboarding_step`).
- 2단계는 1단계 답에 따라 **건너뛴다**. 조건부 단계는 이 하나뿐이다 — 더 늘리면 진행률이 거짓말을 한다.

### 진행률

머리에 얇은 막대 하나. 퍼센트 숫자는 안 적는다 — 조건부 건너뛰기 때문에 전체 칸수가 사람마다 다르고, 숫자가 뒤로 가는 순간 신뢰를 잃는다. 막대만 차오른다.

- 세로 가운데 정렬은 로그인 화면과 같은 방식을 쓴다(`main` 이 flex 기둥, 셸이 `flex-1 justify-center`). 2026-09-22 에 로그인에서 고친 그 사슬이다.
- 머리띠(SiteHeader)와 푸터는 **숨긴다**. 온보딩은 빠져나가는 문이 우상단 ✕ 하나뿐인 화면이다. 라우트 그룹 `(onboarding)` 을 따로 두어 제 레이아웃을 갖는다.

### 카드(선택지) 규격

`components/ui/choice-card.tsx` 로 뽑는다 — 7단계 중 5단계가 같은 카드를 쓴다(규약 §3: 2곳이면 추출).

- 최소 높이 108px, 터치 타깃은 카드 전체(규약 §6 의 44px 을 여유 있게 넘긴다).
- 고른 상태: 배경 `--acc-soft`, 테두리 대신 `shadow-[0_0_0_2px_var(--acc)]`, 좌상단 체크 동그라미가 `--acc` 로 참.
- 안 고른 상태: `--surface-2` 면, 체크 동그라미는 `--line-strong` 윤곽만.
- 접근성: 다중선택은 `role="group"` + `<input type="checkbox" class="sr-only">`, 단일선택은 `role="radiogroup"` + radio. 카드는 label 이다. 키보드로 화살표 이동이 그대로 된다.
- 모션: 누름은 `.press`, 체크는 `animate-pop`. JS 타이머를 쓰지 않는다(규약 §6).

## 5. 동의와 법

**개인화 정보는 선택 동의다.** 가입 약관 동의에 끼워 넣지 않는다.

- 0단계에서 따로 묻는다: "게임 취향을 받아 화면을 맞춰 드릴까요?" + `건너뛸게요`.
- 동의 시각을 `user_profiles.personalization_consent_at` 에 남긴다. 철회하면 `null` 로 되돌리고 성향 값을 **같은 트랜잭션에서 지운다** — 동의 철회가 값 삭제와 따로 놀면 "껐는데 남아 있다" 가 된다.
- 설정 화면에 "개인화 끄기" 와 "받은 값 보기" 를 둔다. 무엇을 갖고 있는지 사람이 볼 수 없으면 동의가 아니다.
- 기기 사양(2단계)은 성향과 **따로 동의**한다. 이미 `user_devices` 가 있고 설정에서 지울 수 있다.
- 약관, 개인정보처리방침 개정은 이 문서와 같은 커밋에서 `src/lib/legal.ts` 에 반영한다(§8).

## 6. 데이터 모델

### 6.1 `user_profiles` — 1사용자 1행

```
user_id            uuid PK FK users(id) on delete cascade
platforms          platform[]        -- 1단계. 빈 배열 = 안 고름
favorite_genres    text[]            -- 3단계. lib/genres 로 정규화한 우리 어휘
deal_style         deal_style        -- 4단계 enum
play_time_style    play_time_style   -- 5단계 enum
subscription_keys  text[]            -- 6단계. subscriptions.key 를 담는다
personalization_consent_at timestamptz
onboarding_step    text              -- 재개 지점. null = 아직 시작 안 함
onboarding_done_at timestamptz
+ auditColumns()                     -- 생성자/생성일/수정자/수정일 4개(전 테이블 규칙)
```

- **배열을 쓰는 이유**: 이 값들은 다른 테이블과 조인할 엔티티가 아니라 *그 사람의 한 시점 취향*이다. 별도 테이블로 쪼개면 행 3개를 읽으려고 조인 3개를 건다. 장르는 `games.genres` 도 텍스트라 `&&`(겹침) 한 번으로 끝난다.
- `platforms`, `favorite_genres` 에 GIN 인덱스. 개인화 목록 질의가 `platforms && $1` 로 들어간다.
- `subscription_keys` 를 FK 로 안 거는 이유: `subscriptions.key` 는 코드가 참조하는 안정 식별자라 행이 지워져도 값이 남는 편이 낫다. 모르는 키는 화면에서 조용히 버린다.

### 6.2 새 enum 둘

```
deal_style:      full_price | wait_small | wait_deep | historic_low
  정가에 산다 | 조금만 깎여도 | 반값은 돼야 | 역대 최저가 아니면 안 산다
  -> price_alerts 기본 임계값: 0 / 20 / 50 / 역대최저

play_time_style: short | medium | long | endless
  5시간 안쪽 | 20시간쯤 | 50시간 넘게 | 끝이 없는 것
  -> HLTB main 값으로 거른다. 시간당 가격 노출 여부도 여기서 갈린다
```

### 6.3 기기는 새로 만들지 않는다

2단계는 이미 있는 `user_devices` 에 그대로 쓴다. `components/devices/detect-button.tsx`, `use-detected-spec.ts`, `lib/hardware/detect.ts` 가 브라우저 추측을 이미 한다. 온보딩은 그 부품을 **한 번 감싸기만** 한다.

- 자동 감지가 GPU 를 못 집으면(사파리는 "Apple GPU" 로 뭉갠다 — `lib/hardware` 주석) 그 칸만 비우고 넘어간다. 온보딩에서 사람을 붙잡고 부품을 고르게 하지 않는다.
- 감지값은 `source: "detected"` 로 남는다. 나중에 판정이 이상할 때 원인을 여기서 찾는다.

### 6.4 마이그레이션

`0043_user_profiles.sql`. 기존 사용자에게는 행을 만들지 않는다 — 첫 진입 때 `upsert` 한다. 미리 만들면 "동의한 적 없는 빈 동의 행"이 생긴다.

## 7. 계층 배치 (규약 §1)

```

lib/onboarding/schemas.ts                  zod. 서버 액션과 클라이언트 폼이 같은 걸 본다
```

- 단계 순서와 문구가 `lib/onboarding` 한 곳에 있어야 단계를 넣고 빼는 일이 파일 하나 수정이 된다.
- 라우트는 `[step]` 동적 세그먼트 하나다. 단계마다 폴더를 만들면 껍데기가 7벌 복제된다.

## 8. 약관, 개인정보처리방침에 더할 것

`src/lib/legal.ts` 에 반영한다. 지어내지 않고 **코드가 실제로 하는 일**만 적는다(그 파일 머리 주석의 규칙).

- 이용약관: 개인화 조항 신설 — 무엇을 받고, 선택이며, 언제든 끌 수 있다는 것.
- 개인정보처리방침:
  - 수집 항목에 `user_profiles` 의 칸들과 `user_devices` 의 부품 값을 **선택 항목으로** 적는다.
  - 수집 목적은 "화면 개인화" 하나다. 광고, 제3자 제공, 프로파일링 판매는 하지 않으므로 하지 않는다고 적는다.
  - 보관 기간: 계정이 살아 있는 동안. 동의 철회 시 즉시 삭제.
  - 자동화된 결정: 사양 판정이 그에 해당하는지 한 줄로 밝힌다. 법적 효과가 없는 추천이라는 점을 적는다.
- 개정일(`REVISED_AT`)을 올린다.

## 9. 회차 나누기

| 회차 | 범위 |
|---|---|
| 1 | 스키마, 마이그레이션, `(onboarding)` 라우트 그룹, 0단계와 1단계(플랫폼), 결과 화면, 약관 개정 |
| 2 | 3단계(장르), 4단계(할인 민감도), 5단계(플레이타임) |
| 3 | 2단계(기기, 기존 부품 감싸기), 6단계(구독), 7단계(웹푸시) |
| 4 | 받은 값을 실제로 쓰는 자리 — 목록 기본 필터, 홈 추천 줄, 알림 기본 임계값 |
| 5 | 설정 화면의 "개인화 끄기", "받은 값 보기", 철회 시 삭제 |

**2단계(기기) 반영 기록(2026-09-25)**: `/welcome/device` 는 플랫폼에서 스팀이나 에픽을 골랐을 때만 연다(플랫폼을 건너뛴 사람도 닫는다).
칸은 비회원 기기 폼과 같은 규칙이다 — 운영체제와 그래픽은 브라우저 감지로 미리 채우고, 프로세서와 메모리는 비워도 된다.
저장은 기존 `user_devices` 에 기본 기기로 한 행(이름 "내 PC"). 이미 기기가 있는 사람에게는 칸 대신 "이미 등록한 기기" 를 보여 주고
더하지 않는다 — 설정에서 적은 기기를 덮거나 같은 기기가 두 대가 되는 것을 막는다. 쓰이는 자리는 따로 만들 것이 없다:
상세의 "내 PC 로 돌아갈까요" 판정과 목록의 사양 필터가 이미 기본 기기를 읽는다.

4회차 전까지는 값을 받아만 두고 화면은 안 바뀐다. **그 사실을 0단계 문구에 적지 않는다** — 대신 4회차를 미루지 않는다. 받아만 두고 안 쓰는 값이 가장 나쁘다.
