## 세로 아트 — 파서가 아니라 주기였다

앞 문서는 이걸 "수집 구멍" 으로 적었다. 아니었다.

- Xbox 표본 12건을 다시 물어보니 **12건 모두 `Poster` 를 준다**. 우리 파서가 첫 번째로 찾는 역할이 그것이다
- 어댑터(`xboxAdapter.fetchMany`)를 그대로 태우면 **12/12 가 세로를 돌려준다**

끊긴 데는 주기다. 정규 수집은 **가격 갱신 차례가 온 게임**만 건드리는데
Xbox 는 하루 1회 × 200건이다(`crawl-prices.yml` 의 예산 주석 + `BATCH_SIZE.xbox`).
ref 12,412건이면 카탈로그 한 바퀴에 **두 달**이고, 그동안 빈 세로 자리는 그대로 남는다.

그래서 그 자리만 고르는 백필을 붙였다(`pnpm portraits:backfill [--source=] [--limit=] [--dry]`).
가격을 쓰지 않고 `games` 의 이미지 두 칸만 반영하므로 정규 수집과 같이 돌아도 가격 이력이 안 흔들린다.
잠금과 덮어쓰기는 `planGameMeta` 를 그대로 부른다.

**한 회차 결과**: 본편 결손 6,107 → 2,511. Xbox 3,679 → 92, steam 25 → 1, epic 4 → 3.
psstore 도 955 → 426 으로 줄었는데 **이건 백필이 한 일이 아니다** — 멀티플랫폼 게임이
Xbox 회차에서 채워지며 같이 빠진 것이다(아래 psstore 절).

### 가릴 때 쓴 방법 (다음에도 이렇게 한다)

"스토어가 안 준다" 와 "아직 안 물어봤다" 는 **표본을 뽑아 어댑터를 직접 태워** 가른다.
DB 의 `last_synced_at` 만 보면 안 된다 — `game_platforms` 를 소스 조건 없이 조인하면
**다른 소스가 갱신한 시각**이 잡혀 전부 "최근" 으로 보인다. 처음에 이걸로 한 번 속았다.

### 대상 기준은 "세로를 준다" 가 아니라 "단건 조회로 준다" 다

`PORTRAIT_SOURCES` 는 **steam, xbox, epic** 셋뿐이다.

- **psstore 를 넣었다가 뺐다**(`804c0f6`). 표본 20건에 0건이 채워졌다 —
  PlayStation 은 상세 응답의 meta 에 이미지를 아예 안 준다(제목 둘뿐이다).
  이미지는 **발견 목록(SearchCandidate)에만** 온다. `store-targets` 의 `coverUrl`, `portraitUrl` 주석이
  "발견 목록에서만 얻을 수 있는 이미지(psstore)" 라고 이미 적어 둔 것이 그 말이었는데 못 읽었다.
  백필은 이미 등록된 게임을 다시 묻는 일이라 발견을 거치지 않는다 —
  넣어 두면 1초에 한 번씩 요청만 쓰고 빈손으로 돌아온다. psstore 의 세로는 **발견이 새로 훑을 때만** 들어온다
- **nintendo, nintendo_jp** — 한국, 일본 eShop 응답에 세로 비율 이미지 자체가 없다.
  그 830건(255 + 575)은 화면의 커버 폴백(DTO v16)이 최종 답이다

소스를 더할 때는 `--source=<소스> --limit=20 --dry` 로 채움률을 먼저 본다.

### 곁가지 — 빈 `external_id` 5,453행은 버그가 아니다

`game_source_refs` 에 `external_id = ''` 인 행이 있다. `matched_by = 'none'` 짝이고
"찾아봤지만 후보가 없더라" 표식이다. `MATCHED_FOR_SYNC` 가 `auto`, `manual` 만 보므로 수집은 안 탄다.

**소스별 통계를 낼 때 이걸 안 빼면 수가 부풀어 보인다** — xbox 본편이 10,601 대 8,432 로 갈린다.

## 매장 3단계

### 앞머리 — 매장 찾기와 매장 페이지

2단계가 반쪽이었다. 승인된 매장주에게 보여 줄 링크가 없어 상태 화면이 "승인됐어요" 에서 끊겼다.

- `/shops` 매장 찾기 — 승인된 매장만, 이름과 주소로 검색
- `/shops/[slug]` 매장 페이지 — 주소, 연락처, 영업시간, 소개, 파는 물건
- 신청 상태 화면에서 매장 페이지로 가는 링크

**거리순이 아니라 이름순이다.** 설계서 §11 은 거리순이라고 썼지만 입점 신청서가 주소를 글로만 받고
`shops.lat/lng` 를 채우는 자리가 없다. 지오코딩을 붙이기 전까지 거리순인 척하는 정렬을 만들지 않는다.

**머리글에 안 올렸다.** 입점 매장이 0곳이라 머리글에 두면 모든 방문자가 빈 목록을 먼저 본다.
푸터에만 달았다 — 회사 목록이 같은 이유로 같은 자리에 있다.

### 본체 — 상품과 재고 (마이그레이션 0033)

설계서 §4 의 층 셋을 그대로 세웠다.

```
games          무슨 게임인가        크롤러 소유   기존
products       무엇을 파는 물건인가   사람 소유     신규
shop_listings  누가 얼마에 몇 개      매장 소유     신규
```

새 표: `hardware_models`, `products`, `product_components`,
`shop_listings`, `shop_listing_units`, `shop_stock_events`.
기종 사전 기본값 15건이 DB 에 들어가 있다(`scripts/seed.ts` 의 `DEFAULT_HARDWARE_MODELS`).

새 화면: `/vendor`, `/vendor/[shopSlug]/listings`(판매 목록, 물건 추가, 재고 인라인 수정),
매장 페이지의 "파는 물건", 게임 상세의 "파는 곳".

### 이 회차의 결정 (다시 묻지 않는다)

- **"파는 곳" 은 `products.gameId` 가 아니라 `product_components.gameId` 로 찾는다.**
  세트에 끼어 있어도 그 게임 페이지에 떠야 한다 — 포켓몬 두 판 세트를 산 사람은
  자기가 찾던 한 편의 페이지에서 그 세트를 만난다. 대표 게임 하나로는 못 하는 일이다
- **매장 데이터에 캐시를 걸지 않는다.** 바뀌는 계기가 크롤이 아니라 사람의 손이라
  `unstable_cache` 를 걸면 승인이나 재고 수정이 한 시간 뒤에나 보인다.
  게임 상세의 "파는 곳" 도 상세 DTO 에 얹지 않고 Suspense 안에서 따로 받는다(찜 버튼과 같은 자리).
  그래서 **DTO 판을 안 올렸다** — 캐시된 모양이 안 바뀌었다
- **상품과 판매 줄을 한 폼에서 받는다.** 두 화면으로 가르면 상품만 만들고 안 파는 행이 쌓인다.
  바코드가 같으면 서비스가 기존 상품에 붙인다 — 바코드가 실물 상품의 자연키다
- 심사 중(pending) 매장 페이지는 404, 정지(suspended)는 "쉬는 중" 을 적고 보여 준다.
  행을 지우지 않는 설계와 같은 결이고, 밖에 걸린 링크가 어느 날 404 가 되는 것보다 낫다
- 재고는 언제나 `available = onHand - held` 를 거친다(§12.1). A 단계에서 held 는 늘 0 이지만
  계산을 서비스 한 곳에 둬야 예약이 붙는 날 화면이 한 줄도 안 바뀐다
- 재고 이력(`shop_stock_events`)은 지금부터 돈다(§12.5). 나중에 켜면 그 전 기간이 통째로 공백이다

### 안 한 것과 이유

- **사진 업로드** — 저장소가 없다. 입점 증빙과 같은 이유로 미뤘다
- **바코드 스캔, CSV** — 손입력이 먼저 서야 그 둘이 무엇으로 들어올지 정해진다
- **`/vendor/[shopSlug]` 요약** — 조회수 세는 자리가 없고 재고 이력이 비어 있다.
  빈 요약을 세우면 매장주가 매번 아무것도 없는 칸을 거쳐 판매 목록으로 간다. 리다이렉트만 한다
- **`games` 의 `origin` / `visibility` / `crawlExcluded`**(§6, §7) — 매장 발 게임 등록은 4단계 몫이다
- `shop_listing_photos`, `shop_channels`, `shop_integrations`

## 검증

`pnpm typecheck && pnpm lint && pnpm test && pnpm build` 넷 다 통과(테스트 848건).
dev 서버(4000)로 `/shops` 200, `/games/<slug>` 200(파는 곳 질의가 실제로 돈다), `/vendor` 307.

**매장을 실제로 만들어 보는 끝단 시험은 안 했다** — 프로덕션 DB 에 시험 매장을 넣는 일이라
사용자 확인 없이 하지 않았다. 배포 뒤 매장 하나를 만들어 승인까지 돌려 보는 것이 남은 검증이다.

## 이번 회차에 배운 것

- **"수집이 안 된다" 를 보면 파서보다 주기를 먼저 센다.** 어댑터는 멀쩡한데 한 바퀴가 두 달이면
  화면에서는 똑같이 "안 들어온다" 로 보인다
- **소스마다 "어느 응답에 무엇이 들었나" 가 다르다.** psstore 는 이미지가 목록에만, Xbox 는 상세에만 있다.
  대상 목록을 만들 때 "그 소스가 그 값을 주나" 가 아니라 **"내가 부를 경로가 그 값을 주나"** 를 봐야 한다.
  20건 dry 로 채움률을 먼저 보면 1분에 드러난다
- `services/*` 는 `import "server-only"` 라 tsx 스크립트에서 못 부른다(3회차에도 적힌 함정인데 또 걸렸다).
  새 질의 검증은 dev 서버로 해당 화면을 여는 것이 가장 빠르다
- `notFound()` 가 이 앱에서는 **본문은 404 인데 상태 코드는 200** 이다. `/games/*`, `/companies/*` 도 같아
  이번에 생긴 문제가 아니다 — SEO 로 문제가 되면 따로 잡을 일
- `scripts/seed.ts` 는 모듈 최상단에서 `main()` 을 부른다. **거기서 상수만 import 하면 시드가 같이 돈다.**
  이번에 기종 시드를 넣으며 한 번 그렇게 됐다(`sync_logs` 확인 결과 크롤은 시작 전에 끝나 피해 없음)
