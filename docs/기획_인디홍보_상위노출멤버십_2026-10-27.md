# 인디 홍보와 상위 노출 멤버십 기획 (초안, 2026-10-27)

사용자 방향(2026-10-27): 인디 게임 개발자나 관계자가 자기 게임을 소개하고, 사람들이 실제로 플레이하게 만드는 것이 먼저다.
수익은 그 홍보 글을 위에 노출해 주는 유료 멤버십에서 낸다.

이 문서는 기획 초안이다. 코드, 스키마는 아직 없다. 결정이 필요한 곳은 맨 끝 "정할 것"에 모았다.

## 1. 지금 있는 것

| 자리 | 하는 일 | 근거 |
|---|---|---|
| 인디 게임 `/indie` | 개발자가 등록한 게임 카드 목록. 승인된 글만 공개 | `indie_posts.review` |
| 인디 상세 `/indie/[slug]` | 그림, 영상, 링크, 정보판, 찜, 신고 | `indie_posts.links`, `youtube_id` |
| 명예의 전당 | 달마다 주목도 TOP 10, 1위 누적 | `hall_of_fame_months` |
| 슈퍼루키 | 승인 30일 안 게임 중 주목도 상위 12 | `reviewed_at` 기준 |
| 게시판 홍보 말머리 | 내가 만든 게임, 진행 중인 프로젝트 | `posts` 카테고리 |
| 개발자 라운지 | 개발일지, 질문과 피드백 | `posts` 카테고리 |
| 게임 상세 인디 마디 | 관리자가 개발자임을 확인한 글만 카탈로그 게임 상세에 붙는다 | `game_link_verified_at` |

## 2. 비어 있는 고리

"소개했다"에서 "플레이했다"까지 가는 길이 화면에 없다.

1. **플레이하러 가는 단추가 약하다.** 링크가 정보판 안 글자 링크로만 있다. 스팀 페이지, 체험판, 웹 빌드, itch.io 중 하나를 고르는 큰 단추가 필요하다.
2. **몇 명이 플레이하러 갔는지 모른다.** 바깥 링크 클릭을 세지 않는다. 개발자에게 줄 수 있는 가장 값진 숫자이고, 유료 상품의 근거가 된다.
3. **플레이한 사람의 말이 쌓일 곳이 없다.** 인디 글에 댓글이 없다(명예의 전당 점수에서도 댓글 항목이 빠져 있다).
4. **다음 소식을 받을 길이 없다.** 찜은 있지만 "출시되면 알려 줘요", "새 개발일지가 올라오면 알려 줘요"가 없다.
5. **플레이테스트 모집이 없다.** 개발 중인 게임이 가장 원하는 것은 테스터다.

## 3. 홍보 흐름 (무료 기본기)

멤버십보다 먼저 만든다. 사람이 오지 않는 자리의 상위 노출은 팔 수 없다.

```
개발자: 게임 등록 → 승인 → 개발일지, 플레이테스트 모집
플레이어: 인디 목록, 홈 줄, 게시판 홍보 글에서 발견
  → "플레이하기"(스팀, 체험판, 웹 빌드) 클릭 집계
  → 찜, 출시 알림, 개발자 소식 받기
  → 플레이 후 댓글, 리뷰(게시판 리뷰에 게임 연결)
개발자: 내 게임 통계(조회, 플레이하기 클릭, 찜, 댓글)를 보고 다음 글을 쓴다
```

| 순서 | 기능 | 메모 |
|---|---|---|
| 1 | 인디 상세 "플레이하기" 큰 단추 + 바깥 클릭 집계 | 클릭은 우리 경유 주소로 세고 바로 넘긴다. 하루 단위 집계 표 |
| 2 | 인디 글 댓글 | 게시판 댓글 부품 재사용. 명예의 전당 점수에 댓글 항목 되살림 |
| 3 | 개발자 소식 받기 | 새 개발일지, 출시를 알림함에 넣는다(알림함은 이미 있다) |
| 4 | 내 게임 통계 화면 | 등록현황 옆. 지난 30일 조회, 클릭, 찜, 댓글 |
| 5 | 플레이테스트 모집 | 기간, 인원, 신청 버튼. 신청자 목록은 개발자만 본다 |

## 4. 상위 노출 멤버십

### 4.1 원칙

- **명예의 전당과 슈퍼루키는 돈으로 못 산다.** 이 둘이 사람들 반응으로 정해진다는 믿음이 서비스의 재산이다. 유료 노출은 그와 다른 자리에 둔다.
- **유료 자리는 "광고"라고 표시한다.** 표시광고법과 공정위 추천보증 심사지침상 돈을 받은 노출은 소비자가 알아볼 수 있게 표시해야 한다. 카드에 작은 "광고" 꼬리표.
- **자리 수를 묶는다.** 한 화면에 유료 칸이 많으면 목록이 광고판이 되고, 산 사람의 효과도 묽어진다.
- **승인, 신고 규칙은 그대로 탄다.** 돈을 냈어도 반려, 숨김 상태면 노출하지 않는다.

### 4.2 파는 자리

| 자리 | 칸 수 | 돌리기 |
|---|---|---|
| 인디 게임 목록 맨 위 "주목할 게임" | 3 | 산 게임이 3개보다 많으면 접속마다 돌아가며 보인다 |
| 게시판 홍보 목록 위 고정 | 2 | 홍보 글 중 산 글 |
| 홈 인디 줄 첫 칸 | 1 | 돌아가며 |
| 게임 상세 "이런 인디 게임은 어때요" | 1 | 같은 장르 우선 |

### 4.3 상품 안

| 상품 | 값(안) | 담는 것 |
|---|---|---|
| 무료 | 0원 | 지금 기능 전부, 3장의 기본기 전부 |
| 인디 게임 부스트 | 7일 6,900원 | 인디 목록 맨 위 7일 |
| 홍보 글 고정 | 7일 6,900원 | 게시판 홍보 목록 위 7일 |
| 묶음(부스트 1회) | 7일 9,900원 | 인디 목록 + 홍보 고정 7일. 낱개 둘(13,800원)보다 3,900원 싸다 |
| 메이커 멤버십 | 월 19,900원 | 매달 부스트 7일 2회, 내 게임 통계 자세히(유입 경로, 일별 그래프), 프로필 인증 꼬리표, 플레이테스트 모집 상단 고정 |

2026-10-27 사용자 확정: 낱개 6,900원, 같이 사면 9,900원, 멤버십 월 19,900원(이용권 한 장 = 낱개 하나). 처음에는 수요를 보려고 낮게 시작하고, 클릭 통계가 쌓이면 "부스트 1회당 플레이하기 클릭 몇 회"를 근거로 값을 정한다.

### 4.4 개발자에게 돌려줄 숫자

산 사람은 효과를 확인하고 싶어 한다. 부스트 기간마다 노출 수, 카드 클릭, 플레이하기 클릭, 찜 증가를 보여 준다.
이 숫자가 없으면 두 번째 결제가 없다.

## 5. 단계

| 단계 | 내용 | 결제 |
|---|---|---|
| 1 | 3장 기본기 1~4 | 없음 |
| 2 | 유료 자리와 "광고" 표시, 관리자가 부스트를 직접 걸어 주는 화면. 시범 개발자 몇 명에게 무료로 줘 효과를 잰다 | 없음(관리자 부여) |
| 3 | 결제 붙이기. 부스트 단건부터, 그 다음 월 정기 | PG 연동 |

결제 연동 후보는 국내 PG(토스페이먼츠, 포트원)다. 월 정기결제는 빌링키 방식이다.
결제를 받기 전에 사업 쪽 준비가 필요하다: 사업자 등록, 통신판매업 신고, 환불 규정(전자상거래법 청약철회, 기간형 상품 일할 환불), 약관과 개인정보처리방침의 결제 항목.

## 6. 데이터 안 (스키마는 정한 뒤에)

모든 표에 감사 칼럼(생성자, 생성일, 수정자, 수정일)을 단다.

- `indie_link_clicks(indie_post_id, day, link_kind, clicks)` 바깥 클릭 하루 집계
- `memberships(user_id, plan, status, started_at, ends_at, billing_ref)`
- `promotion_boosts(target_kind, target_id, slot, starts_at, ends_at, source)` source 는 membership, purchase, admin
- `promotion_impressions(boost_id, day, views, clicks)` 산 사람에게 보여 줄 숫자
- `payments(order_id, user_id, amount, status, pg_tx_id, paid_at, refunded_at)`

## 7. 정할 것

1. 유료 자리 넷 중 어디부터 열지(제안: 인디 목록 맨 위 + 홍보 고정)
2. 값 안(부스트 7일 9,900원, 멤버십 월 19,900원)으로 시범을 할지
3. 사업자 등록, 통신판매업 신고 시점(결제 붙이기 전에 필요)
4. 3장 기본기 1~4를 다음 회차에 바로 만들지

## 8. 개발 범위 (2026-10-27 사용자 확인: 멤버십 관리, 결제, 어드민까지 만든다)

| 영역 | 화면, 기능 |
|---|---|
| 사용자 | 멤버십 안내와 가입, 내 멤버십(남은 부스트, 다음 결제일, 해지), 부스트 걸기(어느 글, 언제부터), 결제 내역과 영수증, 환불 요청, 부스트 성과(노출, 클릭, 플레이하기) |
| 결제 | PG 결제창, 승인 확인 웹훅(위변조 검증), 월 정기결제 빌링키, 결제 실패 재시도와 알림함 안내, 해지 시 기간 끝까지 유지, 환불(전액, 일할) |
| 관리자 | 상품과 값 관리, 회원별 멤버십 목록, 결제와 환불 처리, 부스트 직접 부여와 회수, 유료 자리 현황(지금 걸린 글, 대기열), 광고 글 심사, 매출 요약 |
| 공통 | 광고 표시 꼬리표, 유료 자리 돌리기, 승인, 신고 규칙과 연동(숨김이면 노출 멈춤, 기간은 멈춘 만큼 연장할지 정책 필요) |

만드는 순서: 기본기(3장) → 유료 자리와 관리자 직접 부여(결제 없이 효과 측정) → 부스트 단건 결제 → 월 정기결제.
PG 테스트 키로는 계약 전에도 개발과 시험이 된다. 실결제 전환만 사업자 등록, 통신판매업 신고, PG 계약 뒤에 한다.
