## 1. 값 0 가격 스냅샷 — 해결 (`36738f2`)

### 앞 기록이 틀린 지점

"PS 전용, 나흘에 14건" 으로 남아 있었는데 실측은 달랐다.

- **26건**이고 PS 전용이 아니다 — ps5 22, ps4 2, **xbox 2**
- **26건 전부 다음 회차에 정상값으로 돌아왔다.** 0 이 연달아 두 번 찍힌 적이 한 번도 없다
  (레지던트 이블 빌리지 12,450 → 0 → 11,700). 이게 "오독" 과 "진짜 0원 배포" 를 가르는 유일한 신호다.
- 같은 배치의 다른 항목은 멀쩡했다(한 배치 113건 중 0 은 46건). 배치 사고가 아니라 **항목별 응답 오독**이다.
- 값 0 스냅샷은 전체 1,012건인데 **정가가 있는 것은 저 26건뿐**이다. 나머지는 정가도 0 인 부분 무료 게임이다.
  에픽 146건도 전부 그쪽이라, **에픽 무료 배포가 정가>0 인 0원으로 잡힌 적은 아직 없다**.

### 고친 방식

`server/sync/platform-writer` 의 `priceMisread(snapshot, existingListPrice)` — 정가가 있는데 값이 0 이면
그 회차의 **가격 세 값과 할인 메타를 통째로 버린다**. 기존 값을 지키고 스냅샷도 안 남긴다.
출시일, 버전, 점수처럼 응답의 다른 자리에서 오는 값은 그대로 쓴다.
버린 수는 `ctx.droppedPrices` 로 세어 실행 끝에 한 줄 남긴다 — 실패가 아니라서 sync status 는 흔들지 않는다.

**맞바꾼 것**: 진짜 0원 배포도 같이 버려진다. 살려야 하면 "연속 두 회차가 0 이면 받는다" 로 바꾸는데,
그러려면 직전 회차의 0 을 기억할 자리가 필요하다(지금은 없다 — 컬럼 추가가 필요하다).

화면 쪽 임시 방어(`bestDiscountOf` 의 `listPrice` 인자)는 **걷어냈다**. 수집이 막으므로 화면이 같은
판단을 두 번 할 이유가 없다. 오염된 26건은 `artifacts/zero_price_snapshots.jsonl` 로 백업하고 지웠다
(`scripts/_tmp-zero-price-purge.ts`, 되돌릴 길은 그 파일에 있다).

삭제 자격에 **"다음 회차에 0 이 아닌 값으로 복구됐을 것"** 을 넣었다 — 진짜 0원 배포는 안 걸리게.
결과는 26/26 삭제, 남길 것 0.

## 2. GOG — 화면에서 숨기고 수집 중지 (`742acb1`)

### 왜

**GOG 가 한국에 달러로만 판다.** 우리 gog 행 4,449개가 **한 건도 빠짐없이 USD** 다.
환산 금지(§5) 때문에 `sameCurrency()` 가 원화 행을 남기고 USD 행을 버리므로, 스팀에도 있는
1,063건에서 GOG 는 **이미** 가격 비교와 차트에 안 나오고 있었다. 목록과 배지에만 남은 셈이었다.

> `SOURCE_REGION.gog` 는 `"KR"` 인데 응답은 USD 다. **어댑터가 지역을 잘못 보내는지는 확인하지 않았다.**
> 되살릴 일이 생기면 거기부터 본다.

### 스위치 두 개 — 되살리려면 둘을 같이 뺀다

1. **화면**: `lib/platform` 의 `HIDDEN_PLATFORMS = ["gog"]`
   - 갈래 표 `ALL_FAMILY_PLATFORMS` 는 **전체를 그대로 들고 있다**. 화면용 `FAMILY_PLATFORMS` 가 거른 쪽이다 —
     표에서 빼 버리면 다시 켤 때 어느 갈래였는지가 사라진다.
   - 질의는 `server/db/visibility` 의 `visiblePlatformsOnly()` / `keepVisiblePlatforms()` **한 곳**만 탄다
     (목록, 홈, 상세, 가격, 패치, 회사). 질의마다 손으로 쓰면 한 곳 빠뜨렸을 때 그 화면에서만 되살아난다.
   - 회사 집계만 `leftJoin` 의 `on` 절에 넣었다 — `where` 에 넣으면 leftJoin 이 innerJoin 처럼 굴어
     회사의 게임 수가 줄어든다.
2. **수집**: `adapters/index.ts` 의 `getDisabledReason("gog")`
   - crawl CLI 와 크론 라우트가 비활성 소스를 건너뛴다.
   - 빈손으로 돌지 않게 `vercel.json` 의 gog discover 크론과 Actions 워크플로의 gog 단계도 뺐다.

하나만 빼면 수집은 도는데 화면에 안 나오거나 그 반대가 된다.

### 실측 결과

| | 전 | 후 |
|---|---|---|
| 목록에 서는 본편 | 15,474 | **13,984** |
| 원화 가격이 없는 게임 | 1,490 | **26** (일본 스위치 행) |

**데이터는 안 지웠다.** DB 에 그대로 남은 것: 게임 3,386(본편 1,485, DLC 1,871, 체험판 26, 에디션 4),
가격 스냅샷 4,293, 패치 156, source refs 4,940. 사용자 데이터 걸림돌 없음(wishlists 0, price_alerts 0).

### 곁가지로 나온 것 둘

- **`byPlatformOrder` 가 모르는 값을 앞에 세우고 있었다** — `indexOf` 가 -1 을 준다.
  숨긴 게 섞여 들어오면 제일 먼저 눈에 띄는 자리에 선다. 뒤로 가게 고쳤다.
- **`list.ts` 의 `hasBaseCurrency` 주석이 낡았다** — 그 키를 넣은 이유가 "1,490개가 원화 없음, 거의 GOG"
  였는데 26개로 줄었다. 근거를 다시 적고 키는 남겼다(26개가 첫 화면 먹는 것도 같은 문제고, 지역이 늘면 다시 는다).

## 3. 패치 한글화 — 300건 (커밋 없음, DB 만)

### 진행률도 낡아 있었다

앞 기록은 "1,161건 중 30건" 이었는데 시작 시점 실측은 **1,953건 중 390건** 이었다.

이번 회차에 **300건**을 제목과 요약까지 채웠다. steam 한글 기록 **390 → 690**.

| source | 한글 있음 | 없음 |
|---|---|---|
| steam | 690 | 1,263 |
| gog | 0 | 156 (GOG 를 숨겼으니 **대상에서 뺀다**) |

### 다음 회차용 실측

- **한 회차 300건이 적당하다.** `pnpm patch:ko --export --limit 300` 이면 게임 40개로 묶여 본문 조회 40회로 끝난다.
- **본문은 앞머리 600자만 읽으면 제목과 요약에 충분하다.** 6,000자를 다 읽으면 한 회차에 못 끝낸다.
- **되쓰기 JSONL 을 셸 히어독으로 만들지 마라.** 한글과 따옴표가 섞이면 bash 가 히어독을 못 닫는다
  (이번에 한 번 깨졌다). 파일로 쓰고 `cat >>` 로 붙이는 편이 확실하다.
- 화면 반영은 다음 수집이 그 게임을 건드릴 때다(`game:<slug>` 태그가 그때 깨진다).

## 남은 일 — 다음 세션이 바로 집을 것

우선순위 순.

### A. 비는 크론 몫을 psstore 발견으로 돌린다 (이 회차가 만든 일)

GOG 를 끄면서 `CRON_PLAN.gog` 의 두 자리가 비었다 — prices 400건, discover 190건, 각 약 597초.
`CRON_SOURCES` 와 `CRON_PLAN` 에는 **일부러 남겨 뒀다**(예산 기록이고 라우트가 어차피 건너뛴다).

돌릴 곳은 psstore 발견이다. 병목은 재조회가 아니라 발견이고(psstore 155건 대 카탈로그 7,571건),
부모 없는 DLC 18,642 의 잔여도 "본편이 카탈로그에 없다" 라서 같은 곳을 가리킨다.
`vercel.json` 에 psstore discover 를 한 자리 더 넣고 `CRON_PLAN` 몫을 다시 계산하면 된다 —
**건당 단가부터 실측한다**(신규 등록은 갱신의 4배, 1.8초/건).

### B. 패치 한글화 나머지 1,263건

위 3장의 실측대로 300건씩 4~5회차. 제목만으로도 목록이 읽히므로 급하면 요약을 건너뛸 수 있다.

### C. GOG 지역 파라미터 확인 (선택)

`SOURCE_REGION.gog` 가 `"KR"` 인데 USD 가 온다. 어댑터가 지역을 실제로 보내는지 30분이면 확인된다.
원화를 받을 길이 있으면 2장의 결정 자체가 뒤집힌다.

### D. 데이터 삭제 판단 (서두르지 않는다)
