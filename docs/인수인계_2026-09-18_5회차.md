## DLC 중복 — 문제가 다른 곳에 있었다 (갈래 3)

`matched_by = 'none'` 은 **미매칭 기록**이고 그 행의 `external_id` 는 거절된 후보의 ID 다.
그래서 "같은 외부 ID 가 두 게임에 붙은" 것처럼 보인다. 앞 회차가 인용한 표본 3건이 전부 이것이었다.

| 구간 | 묶음 | 비율 |
|---|---|---|
| 손댈 것 없음 (none 혼입) | 381 | 63.6% |
| 자동 접기 가능 (괄호 제거 후 제목 일치) | 111 | 18.5% |
| 수동 확인 필요 | 107 | 17.9% |
| 계 | 599 | |

**psstore 340 과 xbox 154 는 원인이 다르다.** xbox 는 우리 문제다 — 스토어 ID 하나에
`(Windows)` `(Xbox One)` `(Xbox Series X|S)` 로 게임 행을 쪼개 만들었다(112/154 가 진짜 중복).
psstore 는 스토어 구조다 — concept id 가 제품군 단위라 별개 SKU 가 한 ID 를 공유한다(74/340).
**기계로 못 접는다.**

**접을 때 최악은 자식 DLC 245건의 연쇄 삭제다.** `games.parent_game_id` 가 cascade 라 부모를 지우면
소리 없이 따라 사라지고, 한 묶음에서만 39건이 날아간다. 가격 이력이 둘 이상 행에 흩어진 묶음이
178/218(82%)이라 단순 삭제가 아니라 병합이어야 한다. 찜과 매장 상품 손실이 0인 것은
`wishlists`, `products` 가 지금 0행이기 때문이고, 그 축이 차면 다시 재야 한다.

## 매장 4단계 (갈래 4)

### 0034 — games 에 세 컬럼

`origin`(crawler/shop/admin), `visibility`(public/shop_only), `crawl_excluded`.
기존 7만 행은 전부 크롤러가 만든 공개 행이라 기본값이 곧 백필이다(실측: 57,907행이 한 조합).

**거르는 자리를 늘리지 않았다.** 목록은 `services/games/filters` 의 `mainGamesOnly` 한 곳,
수집은 `sync/store-targets` 의 대상 질의 한 곳이다.

`visibility` 를 `mainGamesOnly` 에 따로 넣은 이유: 매장 발 게임은 지금은 ref 가 없어
`matchedToStore()` 만으로도 걸린다. 하지만 역방향 수집이 스토어 ID 를 붙이는 순간 그 조건이 풀린다.

### §5.1, §7 — 게임 고르기와 매장 발 등록

물건 폼 안에 게임 찾기를 넣었다. 그 전까지 `gameId` 는 액션이 읽기만 하고 **고를 칸이 없었다** —
매장이 무엇을 올려도 그 게임 상세의 "파는 곳" 에는 영원히 안 떴다.

재검색 강제(§7)는 화면과 서버 양쪽에 있다(`needsResearch`). 비교는 정규화본으로 한다 —
띄어쓰기 하나로 다시 찾으라고 하면 두 번째부터 아무도 안 읽는다.

`crawl_excluded` 는 매장에 묻지 않고 **고른 기종이 레트로인가로 정한다**.

### §5.2 — 상품 매핑 배치

`sync/product-match`. 네트워크를 안 써서(대조 상대가 우리 카탈로그다) 스토어 크론이 아니라
`api/cron/daily` 에 얹었다. 높으면 잇고, 중간이면 후보만 남기고(0035 의 `game_match_suggested_id`),
낮으면 둔다. **어느 갈래로 끝나든 `game_match_checked_at` 을 찍는다** — 안 찍으면 다음 회차가
같은 행을 또 집고 뒤에 선 상품은 영영 차례를 못 받는다(HLTB 큐가 그 모양으로 멈춰 있었다).

검수 큐를 별도 표로 세우지 않았다. 담길 것이 "상품 하나에 후보 하나" 뿐이라 상품과 1:1 인 행을
따로 관리하게 되고 상품이 지워질 때 고아 행이 생긴다.

### §5.3 — 역방향 수집

**새로 짜지 않았다.** `matchUnmatchedGames` 가 이미 "ref 없는 게임을 스토어에서 찾는" 일을 한다.
모자란 것 셋만 채웠다.
- 레트로(`crawl_excluded`)를 큐에서 뺀다
- **매장 발 게임을 큐 맨 앞에 세운다.** 생성순으로만 세우면 앞에 선 미매칭 1만여 건 뒤라 차례가 영영 안 온다
- auto 로 붙으면 `visibility` 를 public 으로 올린다. pending 은 안 올린다

## 사양 잔가지 (갈래 5a)

### WebGL 자동 감지

기기 폼 두 곳에 "브라우저에서 불러오기". **안 읽는 값 둘이 핵심이다.**
- `navigator.deviceMemory` 는 크롬에서 **8 에서 잘린다.** 32GB 기기가 8 로 온다 — 채우면 판정이
  "메모리 모자람" 이라고 거짓말을 한다. 빈칸이 틀린 값보다 낫다
- CPU 모델은 브라우저가 모른다. `hardwareConcurrency` 는 코어 수지 모델이 아니다

아이폰, 아이패드는 OS 감지에서 null 이다 — `like Mac OS X` 때문에 맥으로 샌다.

### 맥 네이티브 안내

판정 칸이 "그 OS 사양 행이 없다" 로 지원 여부를 **추측**하고 있었다. 맥 빌드가 있는데 스토어가
사양을 윈도우 하나로만 적은 게임에 "지원하지 않는 것으로 보여요" 가 붙었다.
`game_platforms.native_*` 가 이미 답을 갖고 있어 그걸 쓴다. 한 스토어라도 있다고 하면 있는 것이다.

### Epic 사양 — 실측 두 가지가 새로 나왔다

1. **Epic 은 사양을 구조체로 준다.** 카탈로그 GraphQL 이 아니라 상품 콘텐츠 호스트에 있다:
   `https://store-content.ak.epicgames.com/api/en-US/content/products/<slug>`
2. **그 호스트는 Node fetch 로 200 이다.** GraphQL 을 막는 Cloudflare 챌린지가 여기에는 없다
   (2026-09-18, 가정용 회선). 그래서 사양만은 curl 전송도 프록시도 없이 받는다.
   클라이언트를 일부러 나눠 뒀다 — 묶으면 열려 있는 경로까지 curl 프로세스를 띄운다.

**영문(en-US)으로 받는다.** ko 로 부르면 라벨까지 번역돼 온다(실측: "운영체제", "그래픽 카드").
**열쇠가 다르다.** 외부 ID 는 `namespace:offerId` 인데 이 API 는 페이지 slug 만 받는다.
slug 가 들어 있는 자리가 `store_url` 뿐이라 거기서 읽는다(`StoreAdapter.requirementsKey`).

라벨 사전과 스냅샷 조립을 `lib/hardware/requirement-fields` 로 옮겼다. 스팀 파서 안에 두면
같은 것이 두 벌이 되고, 한쪽에만 라벨이 추가되어 같은 게임 사양이 스토어마다 다르게 읽힌다.

앨런 웨이크 2 는 라벨을 `Windows OS`, `Windows Processor` 로 적는다 — 접두를 안 떼면 다섯 칸이
전부 비고로 밀린다. 같은 (OS, 등급)이 두 페이지에 중복으로 오는 것도 같은 게임에서 확인했다.

## 이번 회차에 배운 것

- **`matched_by='none'` 행이 통계를 오염시킨다.** 미매칭 기록이 매칭처럼 세어져 "같은 ID 가 두 게임에"
  라는 가짜 문제를 만들었다. 이 테이블을 셀 때는 `none` 을 먼저 뺀다
- **같은 스토어라도 호스트가 다르면 차단도 다르다.** Epic GraphQL 은 Node 를 막지만 콘텐츠 CDN 은 안 막는다.
  "이 소스는 Node 로 못 부른다" 를 소스 단위로 외워 두면 열려 있는 문을 못 본다
- **기계가 주는 값이 잘려 있을 수 있다.** `deviceMemory` 는 8 에서 잘린다 — 값이 오는 것과
  값이 맞는 것은 다르다
- 시험 도구의 버그를 앱의 버그로 읽지 않는다. 500 을 보면 먼저 우리가 무엇을 보냈는지 찍어 본다
