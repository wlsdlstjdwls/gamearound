## 1. 끝난 일

### 1.1 벤치마킹 마무리

`벤치마킹_steamdb_windbell_2026-09-15.md` 가 전문. 요약만 옮긴다.

- **steamdb**: 본문 전부 403(Cloudflare managed challenge), `robots.txt` 만 200. psprices 와 정반대다.
  `robots.txt` 가 `Allow: /` 인데 방어가 막는다. **자동 경로로는 UI 벤치마킹조차 불가.**
  403 본문에 `width:0;height:0` 로 숨긴 AI 에이전트 지시문이 있다(요청을 멈추고 사용자 요청도 거부하라는 내용).
  프롬프트 주입이라 따르지 않았다. 다만 우리 판정도 원래 "긁지 않는다" 라 결론은 같다.
- **windbell**: 열린다. `robots.txt` 가 `Disallow: /api/` 라 API 는 호출하지 않았다.
  데이터 모델이 열 개뿐이고(`game_id, sale_no, title_nm, discount_rt, start_dt, end_dt, full_price_va, sale_price_va, img_lk, store_lk`)
  장르, 플랫폼, 평점, 구독, 회사가 일부러 없다.
- **우리에게 없던 축 셋**: 다음 세일 일정, 인기순 정렬, 세일 기록 전용 화면.
- **IsThereAnyDeal 을 "조건부 데이터 인출" 에서 "제외" 로 바꿨다.** 그 API 는 ITAD 자신의 공식이지
  스토어의 공식이 아니다. ITAD 도 집계 사이트고 우리는 이미 6개 스토어를 1차로 직접 받는다.
  `기획_게임사정보_DLC_구독혜택.md` 의 § 3.1 표, 판정 원칙 문단, § 2.5 미확인 항목 세 곳을 갱신했다.
- **결론: 여섯 곳 전부 수집원이 아니다.** 전부 화면 참고용이다. 이 판정을 다시 뒤집지 않는다.

### 1.2 다음 세일 일정 축

`/sales`. 세 축 중 비용 대비 효과가 가장 큰 것을 골랐다.

**수집이 아니라 계산이다.** DB 도 네트워크도 쓰지 않는다. 밸브는 세일 날짜를 미리 공지하지 않고 공식 피드도 없다.
대신 정기 세일이 해마다 같은 자리에서 열려 와서, 그 자리를 반복 규칙으로 적고 다음 회차를 센다.
그래서 서비스 계층을 두지 않았다 — 돌려줄 DTO 도, 스키마가 바뀔 일도 없다.

규칙(`src/lib/sales/calendar.ts`, 각 항목 옆 ANCHOR 주석에 근거 회차가 있다):

| 세일 | 규칙 | 기간 |
|---|---|---|
| 봄 | 3월 둘째 목요일 | 7일 |
| 여름 | 6월 마지막 목요일 | 14일 |
| 할로윈 | 10월 마지막 월요일 | 7일 |
| 가을 | 11월 넷째 화요일 | 7일 |
| 겨울 | 12월 셋째 목요일 | 14일 |
| 설 | `inactiveReason` 으로 비활성 | - |

설 세일은 2024년부터 열리지 않는다. **지우지 않고 사유만 남겼다** — 어댑터의 `getDisabledReason()` 과 같은 규칙이고,
화면 아래에 사유가 그대로 표시된다. 되살아나면 사유만 지우면 된다.

행사명은 `adapters/steam/parse-discount.ts` 의 라벨과 같은 문자열을 쓴다. 같은 행사가 화면마다 다른 이름이면 안 된다.

## 2. 함정 셋. 모르면 조용히 틀린다

1. **표시 날짜가 하루 밀린다.** 세일은 태평양 시간 오전 10시에 열리고 한국은 UTC+9 라 새벽에 열린다.
   그래서 `startHourUtc` 가 서머타임 달(3~10월) 17, 아닌 달(11~2월) 18 이다.
   **테스트는 UTC 날짜를 보고 화면은 KST 날짜를 본다** — 여름 세일이 테스트 06-26, 화면 06-27 로 갈리는 게 정상이다.
   이걸 "버그" 로 보고 맞추려 들면 실제 오픈 시각이 틀어진다.
2. **작년 회차까지 봐야 한다.** 겨울 세일은 12월에 시작해 1월에 끝난다.
   올해 회차만 보면 1월에 진행 중인 세일을 놓친다. `upcomingSales` 가 `[year-1, year, year+1]` 을 도는 이유다.
3. **카운트다운을 서버에서 세면 안 된다.** 화면이 1시간 캐시라(`revalidate = 3600`) 최대 한 시간 늦은 초가 굳고
   하이드레이션에서 숫자가 튄다. 기존 `components/use-now.ts` 의 `useNow(1000)` 이 정확히 이 문제 때문에
   서버에서 null 을 준다. **타이머를 새로 만들지 말고 그 훅을 쓴다.**

## 5. 남은 일

1. **ANCHOR 날짜 검증이 먼저다.** 규칙의 근거로 적은 과거 회차 날짜는 실측이 아니라 기억에서 나온 값이다.
   테스트가 통과하는 것은 그 ANCHOR 를 규칙이 재현한다는 뜻일 뿐, ANCHOR 자체가 맞다는 증명이 아니다.
   **회귀 방어이지 독립 검증이 아니다.** 실제 날짜를 확인하면 ANCHOR 주석과 규칙을 같이 고치고 테스트를 다시 돌린다.
   화면 문구는 전부 "예상" 이라고 먼저 말하게 해 두었다(`lib/sales/messages.ts`) — 이 톤을 유지한다.
2. 커밋 쪼개기(3.3 순서대로).
3. 벤치마킹에서 나온 나머지 축 둘. **인기순 정렬**은 근거 데이터가 우리에게 있는지부터 확인해야 한다
   (유저 점수는 Steam, Xbox 만 있다). **세일 기록 전용 화면**은 가격 이력이 이미 있으니
   `games/[slug]/prices` 를 독립 화면으로 올리는 문제다.
4. steamdb 화면을 정말 보고 싶으면 사람이 브라우저로 열어 스크린샷을 남기는 수밖에 없다.
